Mtodos de reenvo de tramas en Swiches
 Los switches utilizan uno de los siguientes mtodos de reenvo entre puertos de la red:
 Conmutacin de almacenamiento y reenvo (Store and Forward): recibe toda la trama y garantiza que
 la trama es vlida. Si la CRC es vlida, el switch busca la direccin de destino, que determina la interfaz
 de salida. Luego, la trama se reenva desde el puerto correcto. Tiene dos caractersticas: Comprobacin

 Conmutacin de corte (cut-through).: este mtodo de reenvo de trama reenva la trama antes de que
 se reciba por completo. Como mnimo, se debe leer la direccin de destino para que la trama se pueda
 enviar. Es apropiado para los switches que necesitan latencia de menos de 10 microsegundos. No
 comprueba el FCS, por lo que puede propagar errores.
 Una gran ventaja de la conmutacin de almacenamiento y reenvo es que determina si una trama tiene
 errores antes de propagarla. Cuando se detecta un error en la trama, el switch la descarta. El proceso de
 descarte de las tramas con errores reduce el ancho de banda consumido por datos daados.
 El switching de almacenamiento y envo se requiere para el anlisis de calidad de servicio (QoS) en las
 redes convergentes, donde se necesita una clasificacin de la trama para decidir el orden de prioridad del
 trfico. Por ejemplo, los flujos de datos de voz sobre IP deben tener prioridad sobre el trfico de
 navegacin web.

Qu es Inter-VLAN Routing?
 Inter-VLA routing es el proceso de reenviar el trfico de red de una VLAN a otra VLAN.
 Hay tres opciones inter-VLAN routing:
 Enrutamiento entre VLAN (Antiguo o heredado) - No escala bien
 Router-on-a-stick - Esta es una solucin aceptable para una red pequea y mediana.
 Conmutador de nivel 3 con interfaces virtuales conmutadas (SVIs) : esta es la solucin ms
 escalable para organizaciones medianas y grandes.
Antiguo Router-on-a-stick Conmutador de nivel 3 58
Inter-VLAN Routing en el Switch capa 3
 El mtodo moderno para realizar el enrutamiento entre VLAN es utilizar conmutadores de capa 3 e
 interfaces virtuales conmutadas (SVI). Una SVI es una interfaz virtual configurada en un switch
 multicapa, como se muestra en la figura.
 Nota: Un conmutador de capa 3 tambin se denomina conmutador multicapa ya que funciona en la
 capa 2 y la capa 3. Sin embargo, en este curso usamos el trmino Layer 3 switch.
Inter-VLAN Routing en el Switch capa 3 (Cont.)
 Los SVIs entre VLAN se crean de la misma manera que se configura la interfaz de VLAN de
 administracin. El SVI se crea para una VLAN que existe en el switch. Aunque es virtual, el SVI realiza
 las mismas funciones para la VLAN que lo hara una interfaz de enrutador. Especficamente,
 proporciona el procesamiento de Capa 3 para los paquetes que se envan hacia o desde todos los
 puertos de switch asociados con esa VLAN.
 A continuacin se presentan las ventajas del uso de conmutadores de capa 3 para el enrutamiento
 entre VLAN:
 Es mucho ms veloz que router-on-a-stick, porque todo el switching y el routing se realizan por
 hardware.
 El routing no requiere enlaces externos del switch al router.
 No se limitan a un enlace porque los EtherChannels de Capa 2 se pueden utilizar como enlaces
 troncal entre los switches para aumentar el ancho de banda.
 La latencia es mucho ms baja, dado que los datos no necesitan salir del switch para ser
 enrutados a una red diferente.
 Se implementan con mayor frecuencia en una LAN de campus que en enrutadores.
 La nica desventaja es que los switches de capa 3 son ms caros.

 El enrutamiento entre VLAN mediante el mtodo router-on-a-stick es fcil de implementar para una
 organizacin pequea y mediana. Sin embargo, una gran empresa requiere un mtodo ms rpido y

 Las LAN de campus empresariales utilizan conmutadores de nivel 3 para proporcionar enrutamiento
 entre VLAN. Los switches de nivel 3 utilizan conmutacin basada en hardware para lograr velocidades
 de procesamiento de paquetes ms altas que los enrutadores. Los conmutadores de capa 3 tambin
 se implementan comnmente en armarios de cableado de capa de distribucin empresarial.
 Las capacidades de un conmutador de capa 3 incluyen la capacidad de hacer lo siguiente:
 Ruta de una VLAN a otra mediante mltiples interfaces virtuales conmutadas (SVIs).
 Convierta un puerto de conmutacin de capa 2 en una interfaz de capa 3 (es decir, un puerto
 enrutado). Un puerto enrutado es similar a una interfaz fsica en un router Cisco IOS.

 se configuran utilizando el mismo comando interface vlanvlan-id utilizado para crear el SVI de
 administracin en un conmutador de capa 2. Se debe crear un SVI de Capa 3 para cada una de
 las VLAN enrutables.
Enrutamiento en un conmutador de capa 3
 Si se quiere que otros dispositivos de Capa 3 puedan acceder a las VLAN, deben
 anunciarse mediante enrutamiento esttico o dinmico. Para habilitar el enrutamiento en
 un conmutador de capa 3, se debe configurar un puerto enrutado.
 Un puerto enrutado se crea en un conmutador de capa 3 deshabilitando la entidad de
 puerto de conmutacin en un puerto de capa 2 que est conectado a otro dispositivo de
 capa 3. Especficamente, al configurar el comando de configuracin de no switchport en
 un puerto de Capa 2, se convierte en una interfaz de Capa 3. A continuacin, la interfaz
 se puede configurar con una configuracin IPv4 para conectarse a un enrutador u otro
 conmutador de capa 3.

 Ethernet funciona en la capa de enlace de datos y en la capa fsica. Los estndares de Ethernet definen los
 protocolos de capa 2 y las tecnologas de capa 1.

 direccin de la puerta de enlace predeterminada del host (es decir, la interfaz del router). Un dispositivo IPv4
 utiliza ARP para determinar la direccin MAC de destino de un dispositivo local cuando conoce su direccin
 IPv4.

 El dplex completo eliminar los dominios de colisin.
 Un switch inundar todas las interfaces excepto el puerto de entrada si la trama es una difusin o si el MAC
 de destino de unidifusin es desconocido.

 Para el mtodo de router-on-a-stick, se requieren subinterfaces configuradas para cada VLAN que se pueda
 enrutar. Se crea una subinterfaz mediante el comando de modo de configuracin global interface
 interface_id subinterface_id . Necesitarn etiquetado tado IEEE 802.1q proporciona una VLAN nativa que
 permanecer sin etiquetar.
 Es necesario asignar una direccin IP a cada subinterfaz del router en una subred nica para que se produzca
 el routing. Cuando se han creado todas las subinterfaces, la interfaz fsica debe habilitarse mediante el
 comando no shutdown interface configuration.
